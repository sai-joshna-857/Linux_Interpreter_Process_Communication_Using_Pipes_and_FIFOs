WHAT IS BASICALLY HAPPENING?Pipe
💡 SIMPLE IDEATerminal 1 sends a message → the anonymous pipe carries the bytes → Terminal 2 receives the message.
① SENDSender uses write() to put data into the channel.
② TRAVELThe kernel pipe buffer temporarily carries the bytes.
③ RECEIVEReceiver uses read() and gets the same message.
🎓 SAY THIS IN VIVA“A pipe provides a one-way byte stream between connected processes. The sender writes data, the kernel carries it, and the receiver reads it.”

PIPE PROCESS · CONNECTED STREAMWaiting
1 · PIPE CREATEDShell creates the anonymous pipe connection
2 · write()Sender writes bytes into the pipe
3 · KERNEL BUFFERBytes wait inside the kernel pipe buffer
4 · read()Receiver reads bytes from the pipe
5 · RECEIVERTerminal 2 displays the message
1 · SENDER: write()Terminal 1 creates the message and writes bytes into the IPC channel.
2 · THE DIFFERENCEPipe: anonymous kernel buffer, normally used between connected processes. FIFO: named channel such as /tmp/ipc_demo_fifo that separate processes can open.
3 · RECEIVER: read()Terminal 2 reads the bytes from that channel. The message content is the same; the way the two processes access the channel is what differs.
